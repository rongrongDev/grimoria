# Internationalization & Layout — Production Patterns & Common Pitfalls

**Tier:** extended (patterns + pitfalls only). **Scope:** i18n's effect on the *visual layer* — text expansion, RTL, script metrics. String management, locale routing, and translation pipelines are `web-dev/` territory; ICU MessageFormat plurals and the like are not covered here. **Validated against:** CSS logical properties (Baseline 2023), `:dir()` (Baseline 2024), `Intl` APIs (Baseline). **Date:** 2026-07-13.

## The mental model in one paragraph

Localization is the most brutal real-content stress test your layout will ever face (`../principles/responsive-design.md` §2–3 is the foundation; this is its extreme case). Three separate forces: **expansion** — translations are longer, and *shorter strings expand more* (a 4-character "Save" can double or triple; a paragraph grows ~30–35% in German — budget by string length, not by a flat percentage); **direction** — RTL scripts (Arabic, Hebrew) mirror the entire layout, not just the text; **metrics** — scripts have different vertical geometry (CJK and Thai need more line-height; CJK has no spaces, changing how lines break). A layout that treats English as the default and other locales as adjustments will break locale by locale forever; a layout built on logical properties, intrinsic sizing, and tokenized type metrics mostly doesn't notice which locale it's rendering.

## Production patterns

- **Logical properties everywhere, physical properties never (for layout).** `margin-inline-start` not `margin-left`, `padding-block` not `padding-top/bottom`, `inset-inline-end` not `right`, `text-align: start` not `left`. Written this way, `dir="rtl"` on the root mirrors the layout *for free* — flex/grid already flow logically. Physical properties remain correct only for things that genuinely don't mirror (shadows from a light source, media geometry). *Enforcement:* stylelint `csstools/stylelint-use-logical` (or equivalent) — this is a lint rule, not a convention, because muscle memory writes `margin-left` forever.
- **Pseudo-localization in dev builds** — the single highest-leverage i18n practice: a fake locale that pads and accents every string (`[Šàvé çhàñgéš ẋẋẋ]`) plus a mirrored pseudo-RTL. Expansion and direction bugs become visible to every engineer on every feature *before* translators exist. Wire it as a real locale in the i18n framework; add one pseudo-locale story per shared component to the visual matrix (`../principles/visual-regression-testing.md`).
- **Type metrics as per-script tokens.** Line-height, font stacks, and (where needed) size adjustments keyed by script via the token pipeline (`:lang()` scoping or per-locale token sets) — CJK at English line-height clips; Arabic needs taller lines for diacritics. This is the token architecture doing what it's for: the decision made once, inherited everywhere.
- **RTL is mirroring layout, not reversing everything.** Mirrors: reading order, nav position, back/forward chevrons, progress direction, carets. Does not mirror: numbers and phone numbers, media playback controls (play stays ▶), clocks, checkmarks, logos, code. Keep a mirroring inventory for your icon set; give directional icons a logical variant (`icon.chevron.forward`, not `icon.chevron.right` — the token-naming lesson from `../principles/design-tokens.md` applied to iconography).
- **Bidi isolation for user content:** an Arabic username inside an English sentence (or vice versa) scrambles punctuation without isolation — wrap interpolated user strings in `<bdi>` (or `unicode-bidi: isolate`), and use `Intl` formatters for dates/numbers so separators match the locale rather than the developer.

## Common pitfalls

1. **Fixed-width text containers.** The tab bar, the button row, the badge — sized to English, clipped in German, comical in Finnish. *Prevention:* text containers get `min-` sizes and room to grow or a deliberate truncation contract (`../principles/responsive-design.md` §2 arsenal); the pseudo-locale snapshot catches the rest. Special mention: **all-caps labels in wide-glyph languages** — the padded German string in uppercase in a pill badge is the classic first-l10n-release screenshot.
2. **Truncation as the universal answer.** Ellipsizing every expanded string "solves" layout and ships a product where German users can't read their own buttons. Truncate identifiers (emails, filenames — with full value on hover/focus); *wrap* labels and prose; **redesign** any control whose meaning dies under either. If a design only works when the string is short, the design is wrong, not the language.
3. **RTL via `direction` flip alone, untested.** Setting `dir="rtl"` and shipping: physical-property styles don't mirror (half the layout flips, half doesn't — worse than nothing), directional icons point backwards, carousels advance the wrong way. *Prevention:* the logical-properties lint rule closes the first; the mirroring inventory the second; a pseudo-RTL visual pass the third. If you support one real RTL locale, RTL snapshots of money paths are non-negotiable.
4. **Concatenation-shaped layouts.** UI built as `<b>{count}</b> items remaining` in three spans forces word order onto languages that don't share it. This is a string-formatting bug (ICU MessageFormat — `web-dev/` territory) but it *presents* as a layout bug; recognize it and route it to the right fix instead of absorbing it into CSS.
5. **Vertical rhythm assumed constant across scripts.** Line-height tokens tuned for Latin clip Thai stacked diacritics and cramp CJK; baseline-grid perfectionism breaks the moment two scripts share a page. *Prevention:* per-script metric tokens (above); test mixed-script content (an English product name inside a Japanese sentence) in stress stories.
6. **Locale-affected widths beyond translation:** dates ("2026年7月13日" vs "13.07.2026"), numbers (`1 234 567,89`), currency symbols before/after, name order, no-space scripts breaking `word-break` assumptions (`overflow-wrap: anywhere` is Latin-safe but check CJK behavior; `line-break: strict` where Japanese punctuation matters). Use `Intl.*` formatters and include a "widest locale" fixture in numeric-column stress stories.
