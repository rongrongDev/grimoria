# Design-to-Code Handoff — Production Patterns & Common Pitfalls

**Tier:** extended (patterns + pitfalls only). **Validated against:** Figma Dev Mode + Variables (2025 feature set), Code Connect, Tokens Studio, MCP/AI design-to-code assistants (current generation). **Date:** 2026-07-13.

## The mental model in one paragraph

A Figma file is a **picture of one state of the UI on one screen size with one set of friendly data** (`../principles/responsive-design.md` — the mock is the friendliest sample). Handoff tooling — Dev Mode inspectors, Figma-to-code generators, AI assistants — reads that picture and emits code that reproduces the *picture*. It cannot emit what isn't in the picture: behavior under long content, loading/error/empty states, keyboard interaction, what happens at widths the designer didn't draw. The craft of handoff is therefore not better extraction — it's **shrinking what needs to be handed off** (shared tokens and components mean most decisions are already made) and **making the missing states an explicit deliverable** instead of an ambush.

## Production patterns

- **One token source of truth, synced both ways.** Figma Variables and code tokens generated from the same DTCG JSON (Tokens Studio or an equivalent sync pipeline — `../principles/design-tokens.md` §pipeline). Then Dev Mode inspects to *token names*, not raw values — the designer picks `color.text.secondary`, the engineer reads `color.text.secondary`, and nobody transcribes a hex code (transcription is where drift enters). The day the libraries diverge, designers spec values that don't exist; treat sync breakage as a build failure, not a chore.
- **Map the component libraries to each other.** Figma components ↔ code components, formally (Code Connect or a maintained mapping doc), so Dev Mode shows `<Button variant="danger">` — your actual API — instead of generated `<div>` soup. The generated-CSS panel is for *reading measurements*, never for pasting: it describes absolute-positioned picture geometry, not layout intent.
- **The handoff checklist — states the picture doesn't show.** Every screen handed off answers, in the file: longest-realistic content, empty, loading, error, keyboard/focus order for anything interactive, behavior between the drawn breakpoints, dark mode (if themed), and pseudo-locale/RTL if localizing (`i18n-layout.md`). A design missing these isn't done — and it's cheaper for the designer to answer in Figma than for the engineer to invent under deadline and be wrong. This checklist is the single highest-leverage process artifact in this file.
- **Engineers read Auto Layout as intent.** A well-built Figma frame (Auto Layout ≈ flexbox, constraints, min/max) encodes *how the designer thinks it flexes*; a flat pile of absolutely-positioned rectangles encodes nothing. Agree with the design team that shared components are built with Auto Layout + Variables — it's the design-side equivalent of the lint rules in `../principles/css-architecture.md`.
- **AI design-to-code, used where it's strong:** great at first-draft scaffolding of *layout* against your existing components and tokens (point it at the design system, demand it use them — same rules as any contributor, enforced by the same `design-system-consistency-reviewer` skill); weak at exactly what all handoff is weak at — unseen states, a11y behavior, content robustness. Generated code enters through the same PR gate as human code or it's just faster drift.

## Common pitfalls

1. **Pixel-faithful transcription of one state** — the engineer reproduces the mock exactly, fixed heights and all; the first real user name breaks it. The mock was the sample, not the spec. *Prevention:* the checklist above; stress stories as component definition-of-done (`../principles/responsive-design.md` §2).
2. **Values transcribed by eyedropper.** The design uses `gray.600`; the engineer color-picks the anti-aliased pixel and gets `#5F6772`; the drift census grows by one (`../principles/design-tokens.md` §1). *Prevention:* token-synced Variables + inspect-to-token-name; the lint rule catches the leak.
3. **Redlines for a design system that already knows.** Teams annotating padding on every button instance are hand-transmitting information the Button component already owns. If handoff regularly includes measurements *inside* shared components, either the mapping (Code Connect) is missing or the designer is detaching instances — both fixable at the source. Detached instances in Figma are the design-side fork (`../principles/component-api.md` §3): same disease, same governance response — ask why the library component said "no."
4. **The generated-code trap.** Figma/AI-exported CSS pasted into the codebase: absolute positioning, magic numbers, zero tokens, div-soup semantics (`../principles/component-accessibility.md` §3). It demos well and is net-negative by the second edit. *Prevention:* policy — generated output is reference or scaffold-through-review, never merged verbatim.
5. **Handoff as a moment instead of a conversation.** The file is "done," thrown over the wall, and the twenty questions (states, edge cases, intent) arrive as three weeks of async ping-pong. *Prevention:* a 30-minute walkthrough at handoff where the engineer asks the checklist questions live — consistently the highest-bandwidth half hour in the feature's life; the fixed cost is trivial against the ping-pong it replaces.
6. **Design-library version skew.** Code ships v3 Button; the design library still has v2; every new mock is drawn with the old anatomy and every handoff relitigates it. *Prevention:* the design library is a governed consumer of the system like any code consumer — update it inside the deprecation playbook (`../principles/governance.md` §3), not "eventually."
